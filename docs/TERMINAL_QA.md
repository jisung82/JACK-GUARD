## 성능 측정

측정 원본: `assets/screenshots/{100,125,150,200}/performance.json`.
일반 재생(1x, 5개 커서, 녹화 미실행)의 실제 Qt paint 콜백을 계수했습니다.

| Qt 배율 | 완료 시간 | paint 콜백/초 | 최대 timer 간격 | RSS 전→후 | 유휴 CPU |
| --- | ---: | ---: | ---: | ---: | ---: |
| 100% | 2.807초 | 62.35 | 22.63ms | 124.82→125.64MiB | 0.00% |
| 125% | 2.808초 | 62.32 | 22.87ms | 127.35→130.49MiB | 0.00% |
| 150% | 2.810초 | 61.91 | 34.55ms | 129.45→130.35MiB | 0.00% |
| 200% | 2.811초 | 60.48 | 28.29ms | 135.31→136.23MiB | 0.00% |

유휴 CPU는 1.2초 동안 프로세스 user+system CPU 시간 차이를 한 코어 기준으로 계산한
단기 측정값이며, 모든 환경에서 0%를 보장하지 않습니다. 모든 배율에서 완료 후 인트로
타이머가 정지했습니다. RSS는 초기 캡처 전과 두 번 재생 후의 값입니다. 캐시 증가가 포함되며,
장시간 메모리 누수 부재를 증명하는 부하 시험은 NOT_RUN입니다.

paint 콜백/초는 GPU 표시 프레임이나 모니터에 전달된 프레임 수와 동일하지 않습니다.
100%의 GIF 녹화 중 추가 repaint 계수는 성능 표에서 제외했습니다.
최초 200% 구현은 약 47회/초였고 일부 8커서·3x 실행은 약 38회/초까지 내려갔습니다.
전체 이미지·복잡한 clip 반복 대신 실제 필요한 영역만 복사하도록 최적화했고,
자동 모션 감소는 8프레임 평균 간격이 24ms를 넘으면 정적 완성 화면으로 전환합니다.
기기·DPI·부하에 따라 성능은 달라지며 항상 60FPS를 달성한다고 주장하지 않습니다.

## 캡처와 재현

스크린샷과 GIF는 실제 앱 내부 위젯에서 생성했으며 가짜 이벤트나 이미지 합성 UI를 쓰지 않습니다.
캡처에는 테스트 전용 설정·단축키가 표시됩니다. 기본 실제 단축키는 Ctrl+Alt+L/P입니다.

```powershell
$env:QT_SCALE_FACTOR = '1'
python scripts/visual_qa.py --output work/visual --data-dir work/qa-data --gif
```

위 스크립트는 엔진 자체를 명시적으로 재생해 측정합니다. OS 정책 값은 별도로 기록하며,
일반 앱의 인트로·Replay는 항상 Windows 모션 감소 정책을 우선합니다.
