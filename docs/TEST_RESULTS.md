## 발견한 실패와 처리

- 최초 테스트 실행: 임시 디렉터리의 샌드박스 권한으로 8개 setup ERROR.
  작업 폴더 내부 임시 경로로 다시 실행해 29개 PASS, 보호 조건 추가 후 34개 PASS.
- 보호 조건 모의 테스트 초기 작성: ctypes 반환 포인터 형식 오류 2개 FAIL.
  실제 API 버퍼와 같은 포인터로 수정 후 34개 PASS.
- 최초 패키지 실행: QtCore DLL import FAIL (사용자 스크린샷에서도 확인).
  개발 PATH의 Poppler ICU 및 libheif API-set DLL이 잘못 수집됨을 확인.
  빌드 PATH 제한 및 Windows 시스템 구성요소 제외 규칙을 적용한 후 두 패키지 실행 PASS.
- 독립 패키지 스모크 중 실제 GUI 인스턴스가 단축키를 점유해 CONFLICT를 정상 표시.
  검증 인스턴스 종료 후 두 패키지에서 단축키 등록 PASS 확인.
- 재개 후 재검증: 샌드박스의 RegisterHotKey 접근 거부(Windows 오류 5)로
  GUI 테스트 1개와 강화한 패키지 검증이 FAIL. 샌드박스 밖의 같은 등록은 성공.
  앱에서 접근 거부와 충돌(1409)을 구분하고 두 오류를 검증하는 테스트 추가.
  GUI 단위 테스트는 등록 API를 모의 처리하고 패키지 테스트는 임시 설정의
  Ctrl+Alt+Shift+F23/F24를 실제 등록하도록 분리해 외부 앱의 기본 단축키 사용과 격리.
  패키지 테스트는 단축키 등록 실패를 통과 처리하지 않으며 실제 데스크톱 접근이 필요합니다.
